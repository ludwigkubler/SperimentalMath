## Notable findings (handpicked)

1. **`Scrivania/SEC/research/pvsnp_sandbox/` and `.../sandbox_archive/` are 100% duplicates.** Top-issue files like `test_8baeebe4.py` (289 issues each) appear at both locations with identical counts — confirmed by Agent 5 (duplication).
2. **`Scrivania/future/` dominates** the issue volume: `test_1.py` template churn across hundreds of dated dirs. Each `test_1.py` is an isolated LLM artefact, not used in production.
3. **F821 (2,810 undefined names)** is the most worrying number. Sample inspection shows most live inside `Scrivania/future/` LLM scratch files (so they were never meant to run), but the SEC/kissat subset (visible in the F821 sample block above) warrants a hand-check.
4. **`tools/Wav2Lip/`** is third-party code — `inference.py` (244 issues) and `evaluation/*` files are not project responsibility but inflate counts.
5. **F401 (49,527 unused imports)** dominates the metric. `ruff check --select=F --fix` could clear most of these in one pass on the SEC subset.

## Quick wins

- Run `ruff check --select=F --fix` on `~/Scrivania/SEC/src/` only — ~5K issues gone instantly with low regression risk.
- Triage F821 in `~/Scrivania/SEC/` (filter the raw ruff output by system root) — those are the bugs worth fixing.
- Delete one of `pvsnp_sandbox/` / `sandbox_archive/` (one is a mirror) — removes ~140 files of broken autogen code in one action.
