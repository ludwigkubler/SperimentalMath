## D5 — Hourly auto-commits are noise in the git log

`~/Scrivania/SEC/research/git_mirrors/SperimentalMath/` has a job committing every hour with the message `auto: hourly sync YYYY-MM-DD HH:47`. Recent history:

```

83fe7f9 auto: hourly sync 2026-05-13 09:47
f6786ec auto: hourly sync 2026-05-13 08:47
...
```

This makes archaeology painful (`git log --oneline` is hundreds of these). Consider:

- Squash daily into one commit;
- Or have the cron rebase/merge with a meaningful message when a logical change is detected;
- Or move the state-only files (`arxiv_mirror_state.json`, `arxiv_mirror_stats.json` — the two files that are constantly dirty) out of the repo entirely.

## D9 — A second SEC `.venv` and its package divergence

Both `~/SEC/.venv` and `~/Scrivania/SEC/.venv` install many of the same packages but with **different versions / different presence**. Examples from `diff -rq`:

- Only in `Scrivania/SEC/.venv/bin`: `approxmc.py`, `bbscan.py`, `bica.py`, `dotenv`, `fm.py`, `genhard.py`, `huggingface-cli`, `mcsls.py`, `models.py`, `optux.py`, `pdfsampler`, …
- Only in `SEC/.venv/bin`: `diffusers-cli`, `numba`, `lsm2bin`
- Many shared binaries (`accelerate`, `f2py`, `fastapi`, `httpx`, `markdown-it`, `numpy-config`, `normalizer`) **differ byte-by-byte** between the two trees.

So even if you reconcile the source code, you'll need a deliberate decision about which venv (or a single fresh one) is canonical. **Recommendation:** pin a single canonical `pyproject.toml` + `uv.lock`-style lockfile under `~/Scrivania/SEC/`, then rebuild the venv from scratch.
